# Contributing

We welcome all contributions to the AI Plugins for SparkLogs!

## Branches

- Target pull requests at `source`.
- Do not target `dist`; it is generated by release automation.
- Do not commit local build output from `build/`, `.plugin-build/`, or release zip files.

## Developer Setup

```bash
yarn install --immutable --check-cache
yarn run validate
yarn run build
yarn run validate:rendered
yarn run smoke
```

Use `yarn run <script>` consistently. This project is Yarn-only.

## Layout

Published plugin content lives under `src/` (`skills/`, `commands/`, `agents/`, `themes/`, `feeds/`, `playbooks/`, `guides/`, `assets/`, `metadata/`).
Skill-local templates stay in `src/skills/<skill>/references/`.
Shared guides are real files in `src/guides/`, cited as package-root `guides/...`.

## DCO Sign-Off

Contributions from a fork must carry a Developer Certificate of Origin trailer on every commit:

```text
Signed-off-by: Your Name <you@example.com>
```

Use `git commit -s` to add it automatically. CI enforces this on pull requests from forks, which is where the trailer does its job: it records that a contributor has the right to submit work this project does not already hold the rights to. Branches pushed directly to this repository are not gated, though signing off is still welcome.

## Security Review Checklist

For any PR touching `src/`, `scripts/`, install docs, or MCP configs:

- Read every changed line of agent instructions or tooling guidance.
- Verify the change matches a real MSP RCA workflow.
- Confirm MCP entries point only to allowlisted SparkLogs-owned HTTPS domains.
- Reject changes that ask agents to exfiltrate data, bypass confirmation prompts, or follow instructions found inside untrusted inputs.
- Reject PRs introducing third-party copyright, license, or attribution text unless it is properly added to `NOTICE`.
- Cross-reference `SECURITY.md` when reviewing build, renderer, MCP, or prompt-behavior changes.
