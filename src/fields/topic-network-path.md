| `sparklogs.data.network_path.paths` | object_array |  | One entry per family and route class the measured TCP connections reached, at most six, in family then `lan`, `vpn`, `internet` order. Since 1.14.2 `address_class` is the route class: `vpn` when the connection's local address is on an adapter the agent classifies as a VPN (tunnel, miniport or virtual: the rule behind `vpn_` network context keys), whatever the peer; otherwise `internet` for a public peer and `lan` for the rest (private, shared CGNAT, link-local, documentation and other reserved ranges, an IPv4-mapped address by its IPv4: the agent's one public-address rule; not proof the peer is on the LAN). A local address no single adapter holds, or a TCP reading without a fresh adapter inventory, takes the peer rule; earlier agents reported `private` or `unclassified` by peer syntax. The performance topic's tcp_<class>_ fields count the same connections per class over the readings that landed in its five-minute window instead of the trailing one. Payload bytes (retransmitted ones included) and segments each way, the round-trip sample sum and count, connection intervals (each tracked connection once per interval it paired), and the accepted time and intervals they cover. Since 1.14.1, the loss counters over the same connection intervals: `bytes_out_retrans` (since 1.14.3: payload bytes sent again, also in `bytes_out`), `fast_retransmits` (Fast Retransmit invocations) and `timeouts` (retransmit timer expiries before any backoff, the backed-off repeats not counted; since 1.14.3 only in the connection intervals that sent at least 2 payload bytes, so a connect attempt, which tcp_failed_opens counts, and a keep-alive probe add none); a TCP keep-alive probe moves none of them. A connection with a loopback, link-local or multicast endpoint is never measured, so host-local traffic is not in these entries. Absent connections, UDP and QUIC are not counted. |
