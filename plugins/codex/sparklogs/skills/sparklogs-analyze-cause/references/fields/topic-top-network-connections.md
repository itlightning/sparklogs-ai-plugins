# Top network connections fields

Reported every 5 minutes on clock boundaries for the window ending at `t`. `sparklogs.window_coverage_pct` is below 100 when collection covered only part of the window. Use chart buckets at least 5 minutes wide.

| Field | Type | Unit | Meaning |
|---|---|---|---|
| `sparklogs.data.top_network_connections.connection` | string |  | The row's key: a label for the TCP connection, with the remote address shown under the workspace's privacy setting. The local end comes first; `->` marks an outbound connection, `<-` an inbound one and `--` an unknown direction. |
| `sparklogs.data.top_network_connections.entry_kind` | string |  | What the row is: `connection` (one TCP connection), `process_internet` (one process's internet connections to one port, combined) or `remainder` (everything not listed, one per scope). TCP only; UDP and QUIC are not counted. |
| `sparklogs.data.top_network_connections.transport` | string |  | The protocol these rows measure: always `tcp`. |
| `sparklogs.data.top_network_connections.top_by` | string_array |  | The rankings that listed this row: `rx` and `tx` each list the ten busiest; `total` fills up to forty rows above a minimum traffic rate; `struggling` lists up to five more connections in trouble and also tags listed rows that are. A connection is struggling when, over the window, it had at least two retransmit timeouts, a timeout in this window and the one before, a high share of resent data while sending a meaningful amount, or a stall it recovered from (repeated timeouts, then data getting through again). One timeout on an otherwise quiet connection, such as a pooled keep-alive, does not count, and duplicate acknowledgments never do. A `process_internet` row is struggling when one of its connections is. A connection that closed during the window can still be listed. Empty on remainders. |
| `sparklogs.data.top_network_connections.direction` | string |  | `inbound` or `outbound`, worked out from the ports the same process listens on. Absent when the agent could not tell, or combined connections disagree. |
| `sparklogs.data.top_network_connections.scope` | string |  | `internet` for a public remote address, `local` for any other. |
| `sparklogs.data.top_network_connections.family` | string |  | The connection's IP family: `ipv4` or `ipv6`. Absent on combined and remainder rows. |
| `sparklogs.data.top_network_connections.pid` | integer |  | The ID of the process that owns the connection, as Windows reports it. Absent on remainders and when combined connections disagree. Connections served by kernel-mode servers, such as SMB, show as System. |
| `sparklogs.data.top_network_connections.create_time_ts` | string | timestamp | When the owning process started, in UTC. Absent when the agent could not confirm the process, or combined connections disagree. |
| `sparklogs.data.top_network_connections.image_name` | string |  | The owning process's executable file name. Absent when the agent could not confirm the process, or combined connections disagree; when absent but `image_path` is present, take the file name from the path. |
| `sparklogs.data.top_network_connections.image_path` | string |  | The full path of the owning process's executable. Absent when the agent could not confirm the process, or combined connections disagree. The agent never collects command-line arguments. |
| `sparklogs.data.top_network_connections.local_address` | string |  | This machine's address on the connection, with any IPv6 scope ID. Absent on combined and remainder rows. |
| `sparklogs.data.top_network_connections.local_port` | integer |  | This machine's TCP port; on an inbound combined row, the listening port. Absent on outbound or unknown-direction combined rows and on remainders. |
| `sparklogs.data.top_network_connections.remote_address` | string |  | The remote address: in full for a non-public address; for a public one, in full, as a prefix or as an opaque ID, per the workspace's privacy setting. Absent on combined and remainder rows. |
| `sparklogs.data.top_network_connections.remote_port` | integer |  | The remote TCP port; on an outbound combined row, the service port. Absent on inbound or unknown-direction combined rows and on remainders. |
| `sparklogs.data.top_network_connections.connections` | integer |  | How many connections with traffic this row covers. Absent on remainders, which have no exact count. |
| `sparklogs.data.top_network_connections.rx_bytes_5m` | integer | bytes | TCP payload received over the measured part of the 5-minute window. When the agent tracks more connections than it can list, the remainder rows carry the bytes of those left out. |
| `sparklogs.data.top_network_connections.tx_bytes_5m` | integer | bytes | TCP payload sent over the measured part of the 5-minute window, resent data included. When the agent tracks more connections than it can list, the remainder rows carry the bytes of those left out. |
| `sparklogs.data.top_network_connections.rx_bytes_per_s_avg` | float | bytes_per_second | The average rate TCP payload was received over the measured part of the window. |
| `sparklogs.data.top_network_connections.tx_bytes_per_s_avg` | float | bytes_per_second | The average rate TCP payload was sent over the measured part of the window, resent data included. |
| `sparklogs.data.top_network_connections.tcp_retransmit_pct_avg` | float | percent | Resent payload as a percentage of payload sent, at most 100. A minimum divisor keeps a nearly idle connection's one resent segment from reading as a large share. 0 when nothing was sent. |
| `sparklogs.data.top_network_connections.tcp_timeouts` | integer | count | Retransmit timeouts in the window: a stall, as opposed to the quick resends of mild loss. Counted only while the connection was sending data, so connection attempts and keep-alives add none. Adds up across windows and rows. 0 when none. |
| `sparklogs.data.top_network_connections.tcp_dup_ack_episodes` | integer | count | Runs of duplicate acknowledgments this machine sent, each a segment lost or reordered on its way here (download loss). Counted only for connections that received a meaningful amount of data in the window, so keep-alive traffic adds none. Read against `tcp_data_segments_in_5m`. Adds up across windows and rows. 0 when none were counted; absent when the receive statistics could not be read for this row's connections. |
| `sparklogs.data.top_network_connections.tcp_data_segments_in_5m` | integer | count | Segments carrying data that this row's connections received in the window, resent ones included, counting the same connections as the duplicate-acknowledgment count. Adds up across windows and rows. 0 when those connections received too little to count. |
| `sparklogs.data.top_network_connections.timeout_connections` | integer | count | On a remainder only: how many of its connections had at least one retransmit timeout, showing how many more connections stalled than the listed rows name. 0 when none. |
| `sparklogs.data.top_network_connections.rtt_ms_avg` | float | milliseconds | The average round-trip time over the window's samples. Absent without a sample. |
| `sparklogs.data.top_network_connections.rtt_sample_count` | integer | count | How many round-trip samples the average is taken from. Adds up across windows and rows. 0 when none. |
| `sparklogs.data.top_network_connections.rtt_min_ms` | integer | milliseconds | The lowest round-trip time any of the row's connections measured since the agent began tracking it, in whole milliseconds (a LAN often reads 0). It does not reset, so on a long-lived connection a rise in `rtt_ms_avg` above it shows a slower path or queueing, but only when the connection was sending enough data per sample; on light traffic the gap is the peer's delayed acknowledgment. Absent without a sample, and on remainders. |
| `sparklogs.data.top_network_connections.destination_mode` | string |  | The workspace's privacy setting for remote addresses when the window closed: `full`, `prefix`, `opaque` or `aggregate`. |
